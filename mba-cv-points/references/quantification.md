# Quantification Toolkit

~87% of corpus bullets contain a number, and ~74% put one in the first six words. Quantification is
the soul of this style. This file is the toolkit for adding credible, well-formatted numbers.

## What to count (in rough priority)
1. **Money** - revenue, cost saved, budget, sponsorship, deal/book size. (Rs/$/EUR)
2. **Percentages** - improvement, growth, reduction, share, accuracy. (the #1 unit; ~1 in 5 bullets)
3. **Multiples** - "3x faster", "10x speedup", "doubled".
4. **Scale/counts** - people, teams, users, clients, events, sites, SKUs, data points.
5. **Time** - hours/days/weeks/months saved or duration.
6. **Selectivity** - 1/N, "out of N", percentile, rank.

## Number formatting (match the corpus)
- **Indian scale:** `k` (thousand), `L` / `lakh` (1,00,000), `Cr` / `crore` (1,00,00,000).
  Currency prefix: `Rs` (or the Rupee symbol on the real CV). e.g. `Rs50L+`, `Rs2Cr/year`, `Rs70k`.
- **International scale:** `mn` (million), `bn` (billion). e.g. `EUR45bn+ book`, `$5mn`.
- **The "N+" pattern (very common - 39k uses):** append `+` to mean "at least / more than":
  `5+ vendors`, `10k+ MRI slices`, `200+ studies`, `500+ attendees`, `Rs1.2Cr+`.
- **Percentile / rank:** `99.28%ile`, `AIR 604`, `Int'l Rank 249`, `Top 0.5%`.
- **Selectivity:** `1/12 selected`, `1/23 out of 102 applicants`, `1 of 20 teams`.
- **Ranges & before/after:** `1.7s to 0.0535s`, `9% to 83%`, `30/30 in Reading`.
- Use digits, not words, for anything countable ("3 stores" not "three stores") - though the corpus
  occasionally spells small numbers; digits are safer and shorter on a one-page CV.

## Turning a vague claim into a measured one
Ask these to surface a real number:
- "How much / how many?" -> add the count or amount.
- "Compared to what / from what to what?" -> add the baseline (before->after, or vs benchmark).
- "Over what period / at what scale?" -> add time or population.
- "How selective was it?" -> add 1/N or out-of-pool.

| Vague | Measured |
|-------|----------|
| Improved process efficiency | Cut cycle time 40% (5 hrs -> 3 min) by automating preprocessing |
| Raised a lot of money for the fest | Raised Rs4L+ sponsorship from 8 partners for an 8k-footfall fest |
| Did well in CAT | Secured 99.75%ile in CAT (out of 3.3L candidates) |
| Led a big team | Led 80+ volunteers across 6 events at the university E-Summit |
| Built a model with good accuracy | Built a model hitting 98.6% accuracy, cutting errors 22% |

## Honesty guardrails
- Never fabricate a figure. If the user doesn't have it, write the structure and bracket the gap:
  `Reduced TAT by [X]% - add real figure`.
- Prefer a defensible precise number over an impressive round one you can't source.
- Don't double-count or stack unrelated metrics to look bigger; one clear metric beats three fuzzy ones.
- Percentages need a base - "improved 200%" from a tiny base can mislead; keep it honest.
